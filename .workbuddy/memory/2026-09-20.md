### 登录框架（M0）落地

- 建出可编译运行的安卓工程并装进 MuMu：AGP 8.7.3 / Kotlin 2.0.21 / Compose / okhttp 4.12.0，纯命令行 `gradle --offline :app:assembleDebug`。提交 f648cfa。
- 目录结构：`core/JxauLog`（双通道日志 TAG=JXAU_NET）、`data/model`、`data/net/{SiteProfiles,Http,CasRsa,CasAuth}`、`data/{SessionStore,SessionRepository}`、`ui/login/{LoginViewModel,LoginScreen}`、`ui/theme`。
- **实测确认的三条协议事实**（都写进代码注释了）：
  1. CAS 登录成功后**必须用 TGT 重新换针对 jwgl 的 ST**。登录响应里同时有 TGT 和 ST，但那个 ST 是按 `service=portal.jxau.edu.cn/shiro-cas` 签发的，拿去换教务系统会话只会拿到 ASP.NET_SessionId、不会跳 `/Main/Index/{uuid}`。脚本 `_refresh_portal_session_from_tgt` 也是始终走 TGT→ST。
  2. 密码错误时 CAS 返回 `PASSERROR`（脚本的 error_map 里没有这个码），body 形如 `9,1` = 已错 1 次 / 达 9 次锁定。所以错误文案要**先判计数器再查表**。
  3. 兑换会话那一步脚本用的是**全新 `requests.Session()`**（空 CookieJar），所以安卓侧必须在兑换前 `clearHost(jwgl)`，否则上次失败留下的陈旧 ASP.NET_SessionId 会跟着新 ST 一起发出去。
- 静默失效修复：`login()` 失败后调 `refreshCaptcha()` 会被 `if (busy) return` 挡掉 → 验证码不刷新 → CAS 一次性验证码导致重试永远报「验证码错误」。抽出无守卫的 `loadCaptcha()`。
- 判据修正：`headerForHost` 非空 ≠ 拿到了正确会话 Cookie。新增 `hasCookie(host, name)`，用真名做检查（对应脚本 `cookie_name`）。WebVPN 的会话 Cookie 名实为 `wengine_vpn_ticketwebvpnnew_jxau_edu_cn`（带 new），此前写错。
- 补了全局 User-Agent 拦截器：OkHttp 默认**不发 UA**，而脚本每条请求都带，学校侧有 WAF。
- adb 坑：每次 Bash 调用 adb daemon 都会重启，必须把 `connect` 和命令放在**同一次调用**里，并用 `-s 127.0.0.1:7555` 显式指定设备（否则报 more than one device/emulator）。
- 删掉 tools/probe_login.py：它开头 `logcat -c` 会清掉人工操作现场的日志，且 find_editable 过滤有 bug。
- 待验证：修复后的 ST 兑换尚未跑通真实登录。

### 关键事实（推翻旧结论，已同步改文档）
- **`Sjd` 不是节次序号**，是 `(星期-1)×10 + 节次块序号` 的拼接。
  实测 `11`/`21`/`31`/`41` 全是「上午 1-2节」，`09`/`19`/…/`69` 全是「白天 1-8节」。
  拿它排序会把行序排错。排周课表的行必须从 `Jieci` 解析节次区间。
  文档里原来写的「`Sjd` 是两位数字代码取节次」是错的，已改正。
- `Jieci` 一学期出现 7 种：`白天 1-8节`(全天) / `上午 1-2节` / `上午 3-4节` /
  `下午 5-6节` / `下午 5-7节`(三节连排) / `下午 7-8节` / `晚上 9-11节`。
  `白天 1-8节` 与其它行重叠，单独占一整行。
- **行集合必须取自整学期，不能按当前周归纳** —— 否则切到没排该课的周时行会消失，整张表跳一下。
- 课表接口**不返回 totalCount**，一次给足 `limit=1000`。
- **周次锚点**：服务端没有开学日期。用考试安排的「`Kszhou` 周次 + `Ksday` 该周内日期」反推第一周周一。
  实测 3/3 一致 → 2026-08-31；2026-09-20 = 第 3 周。取多数票并把「N 条中 M 条一致」显示给用户；
  推不出来不猜，退回第 1 周并明说「请手动选周」。
- `Ksday` 是 `2026-9-11` **不补零**形态，ISO 解析器吃不下（Kotlin `LocalDate.parse` 抛异常，
  Python `date.fromisoformat` 同样抛），必须自己兜底拆 `y-M-d`。

### 接口层的诚实性约定（新增，后续沿用）
`JwglApi` 所有 fetch 返回**可空**：`null` = 请求/解析失败，`emptyList` = 请求成功但确实没数据。
原来两者都返回空列表，UI 只会显示「本学期没有课」，而真实原因可能是会话已失效。
`fetchAllRows` 任何一页失败都返回 null，不返回「已抓到的部分」——半份课表比没有课表更危险。

### 成绩接口的坑（两个都改进了文档）
- **`totalCount` 返回 0**：有 27 行数据但 `totalCount=0`。
  直接拿它当分页终止条件（`已抓行数 >= 0` 恒真）会在第一批就退出，
  **静默截断成只有第一页**。已在 `JwglApi.fetchAllRows` 修：`<= 0` 视为「没给总数」，
  退回靠「本页行数 < limit」判断。这个 bug 在课表页就有隐患，只是恰好没触发。
- **`Jgbj` 是三态不是布尔**：`0`=不及格(3 条) / `1`=及格(21 条) / `2`=补考行(3 条)。
  原模型写成 `passed = (Jgbj == 1)`，把后两种状态都丢了。已改为 `PassState` 枚举。
- **`Jgbj == 1` 不代表 `Zpcj >= 60`**：大学语文(55→补考 69)、高等数学D1(56→补考 71)
  被补考救回后 `Jgbj` 变成 1，但 `Zpcj` 仍是正考分。按分数<60 标红会错标这两门。
- **`Point` 只有 4/27 条是真值**（其余 -1.0）。其中无补考的两条精确符合 `(分-50)/10`，
  两条补考救回的固定是 1.5，不符合任何分数公式。**样本不足，不推断学校算法**，
  因此 App 里**刻意不算平均学分绩点**，只原样展示服务端给的值。
  → 待确认：学校对补考及格的绩点是否统一按 1.5 计。
