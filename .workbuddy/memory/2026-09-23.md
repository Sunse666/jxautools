## 缺陷诊断：切页时的「字符粘连」（只诊断，未改代码）

用户报告：切到别的页面时上一页的字短暂残留，新页控件直接盖在其上，过一会儿才消失。

**根因（四环机制链，每环都有代码位置）**：
1. `AnimatedContent` 的过渡语义就是「旧内容在过渡期内**仍在组合树里、仍被绘制**」——
   项目自己的注释已写明（`Motion.kt:141-144`、`AppRoot.kt:97-101`）→ **残留窗口 = 过渡时长**
   （`Swap 170` / `SlideOut 200` / `SlideIn 260`，`Motion.kt:51-62`）。过渡一结束旧内容被移出树 → 残留消失。
   这就是「过一会儿才消失」的全部来源。
2. 两个页面根节点**都是透明的**：全应用唯一不透明底在 `MainActivity.kt:77` 的根 `Surface`，位于两层**之下**；
   页面根一律是裸 `Column(fillMaxSize())`（`GradeScreen.kt:69`、`TimetableScreen.kt:69`、`RushScreen.kt:61`、
   `LoginScreen.kt:83`）。`AppRoot.kt:110` 的 Scaffold 容器色同样在两层之下。
3. **进入层带 `fadeIn`**（`Motion.kt:121` / `Motion.kt:165-169`）→ 整棵子树（含将来的底色）整段过渡期半透明。
   **所以「给根节点加底色」单独并不够** —— 这是最容易误判的一环。
4. 盖得干净的只有自带不透明容器色的部件：顶栏 `AppBars.kt:62`、各类 `Card` → 视觉上就成了
   「新页控件盖住旧字、字还在控件之间露出来」。

**放大器（两条未实测，已在文档里标出）**：`SizeTransform(clip = false)`（`Motion.kt:232`）对整屏+半屏横移
不可见，但对小于屏幕的容器会露出来（`ProfileScreen.kt:156` 子页 Pager、`SelectionScreen.kt:112` 两半）；
嵌套过渡（`AppRoot.kt:59` → `AppRoot.kt:129` → 页内 `MotionSwap`）；掉帧把动画时钟时间映射成更长的真实时间。

**修复三档**：A 过渡层每层自带不透明底（前提，一处改全应用生效）· B1 `MotionPager` 去掉进入侧 `fadeIn`
（根治页面级）· B2 `MotionSwap` 把进入侧 alpha 压到 ~90ms 或 `EnterTransition.None` · C 容器加 `clipToBounds()`。
**核心判断：页面级切换不该用交叉淡入 —— 只要进入层 alpha 从 0 开始，重影就是必然，调时长只是缩短它。**

**这次没验的（保持诚实）**：绘制顺序按现象取用（没从字节码核）；`clip=false` 的实际可见性；掉帧的贡献。
诊断全文写进了 `docs/UI改造实施大纲.md` §10（含判据、代码位置、方案表、验证方式）。**代码一行未改**，
等用户拍板用哪一档。

## 参考基准：Pixel / Material 3 的过渡规格（已联网核数值，写进大纲 §10.7）

**最关键的一条（也是修法的依据）**：Material 是**「先出后进」，两个 alpha 窗口零重叠**。
官方 Compose 参考实现的原文数值：

```
SharedAxisX   进 = fadeIn(210, delay = 90) + slideInHorizontally(300) {  30.dp }
SharedAxisX   出 = fadeOut(90)             + slideOutHorizontally(300) { -30.dp }
FadeThrough   进 = fadeIn(210, delay = 90) + scaleIn(0.92f, 210, delay = 90)
FadeThrough   出 = fadeOut(90)
Fade          进 = fadeIn(45) + scaleIn(0.8f, 150) ｜ 出 = fadeOut(75)
```

退出 0–90ms 淡完 → 进入 90ms 才开始变亮、300ms 结束。**任何一帧只有一页在画** ——
这就是 Pixel 上看不到本缺陷的机械原因。我们现在的写法是 `fadeIn togetherWith fadeOut` 同起同止，
整个窗口都在重叠。

**三层结构要分清**（别再混着说）：系统层（窗口级，每个 Activity 独立窗口自带不透明底，
预测式返回由**手势进度**驱动、无固定时长）· 应用层（shared axis / fade through / container transform，
**Material 指定底部导航 Tab 用 fade through**）· 数值层（M3 tokens：短 50/100/150/200 ·
中 250/300/350/400 · 长 450/500/550/600；缓动 emphasized `(0.2,0,0,1)`）。

**三条修正**（比 §10.4 初版更准）：
1. B1 **不该写成「去掉 `fadeIn`」，而是「改成错开结构」**（保留 fadeIn + 90ms 延迟）——
   零重影且不丢淡入手感，数值直接抄官方。
2. `MotionPager` 位移从 **`it / 2`（半屏）改成 30dp**（固定，不随屏宽）。
3. **A（页面根补底色）从"前提"降级为"可选加固"**：错开结构下进入层变亮前旧层已 alpha=0，透不出来。

**已确认不用动的**：`MotionEasing` 三条就是 M3 的 Emphasized / Decelerate / Accelerate（`Motion.kt:81-91`）；
时长量级 170/200/260 也在 M3「中」档范围内。

**待拍板的语义差异**：Tab 切换 Material 规定用 fade through（同层级、无方向），我们用了方向性滑动。
我倾向保留滑动但按 SharedAxisX 数值改；`ProfileScreen` 首页↔子页是明确层级关系 → 标准 SharedAxisX。

## 复分析「页面缺不透明底」（11:00，**Kotlin 一行未改**）

用户第二次报告同一现象，这次归因为「每个页面底部缺少完整的不透明底层背景」。

**几何怎么定的（不靠眼睛估）**：源图是**规则 5×5 网格**（格边界与等分网格最大偏差 **0.40px**），
图形外接框 21..234（214px，占画布 83.6%）。官方规范**联网核过**：108dp 画布 / 72dp 可见区 / 66dp 圆安全区，
外层 18dp 只给视差动画。取**外接框 72dp**（18..90），每格 14.4dp，8 个矩形合并覆盖 14 个亮格。

**「格中心采样只能判格级、判不出格内尺寸」这条是探针实测出来的，不是推理出来的**（实测差异率 0.781%）。

**又抓到一条反向的**：底部横条变短时，缺掉的那块正好被右列矩形**完全覆盖** → 图形其实没变，
