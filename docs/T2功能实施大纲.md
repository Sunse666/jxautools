## 0. 本轮范围与三个前提判断

### 0.1 为什么砍掉 T1-P2

「今日课程通知」的通病不是技术难度，而是**它拿不到我们缺的那个数据**：

| 维度 | 判断 |
|---|---|
| 数据 | 只能算出「第几节」，**给不出「几点几分」**（节次钟点表至今没找到，见 §6.1） |
| 替代品 | 系统日历（.ics 可精确到分钟）、班级群、课表截图，都比"某节课前 N 分钟"更早、更准 |
| 情境 | 一个学生一天最多被提醒 1–2 次，且**看到通知也做不了任何操作**（不是可行动的提醒） |

结论：**投入产出比不成立**，与「考试安排 .ics 导出」那种「导进去就一劳永逸」的功能不在一个量级。

> ⚠️ **但 P2 代码里有一件不是"功能"而是"缺陷修复"的东西**：`BootReceiver` + `RECEIVE_BOOT_COMPLETED`。
> 项目既有缺陷是「**设备重启后所有定时静默丢失**」，而定时是**抢课**功能的底座 ——
> 抢课是 App 的核心卖点，重启后闹钟丢了却没有任何提示，属于真缺陷。
> 这一条**保留并单独提交**，只砍「每日课程提醒」那部分。

#### 0.1.1 清理执行记录（2026-09-22 已完成）

**保留**（抢课定时的持久化 + 开机恢复，这一批是缺陷修复）：

| 文件 | 说明 |
|---|---|
| `service/BootReceiver.kt` | 新增。四个广播（`BOOT_COMPLETED` / `MY_PACKAGE_REPLACED` / `TIME_SET` / `TIMEZONE_CHANGED`）上重排。**故意不含 `LOCKED_BOOT_COMPLETED`**，见下 |
| `data/PendingTaskStore.kt` | 新增。替代原 `OfflineStore`，**只留**「待触发的抢课时刻」这一项 |
| `service/RushScheduler.kt` | `schedule`/`cancel` 落盘 + 新增 `restorePending`（过期则丢弃并归零） |
| `service/RushAlarmReceiver.kt` | 触发后把落盘时刻清零，避免重启时被当成"未执行的定时" |
| `MainActivity.kt` | `applyAlarms()` 兜底（App 启动是唯一一定会发生的事件）+ **撤销旧版本留下的幽灵闹钟** |
| `AndroidManifest.xml` | `RECEIVE_BOOT_COMPLETED` + `BootReceiver` 声明 |
| `ProfileViewModel.logout()` | 退出登录时撤掉待触发的抢课闹钟（否则「退出后还会自己抢课」） |
| `tools/verify_boot_restore.py` | 三轮：未来补排 / 过期丢弃 / **关掉接收器的变异探针** |

> 🔎 **清理时撞出来一个真问题（已修）**：把接收器删掉、装上新包之后，
> `dumpsys alarm` 里那颗每日提醒闹钟**还在** —— **`AlarmManager` 的闹钟不随包更新消失**
> （系统持有的 `PendingIntentRecord` ≠ Manifest 里的 `<receiver>` 声明）。
> 它到点会触发一次，而接收器已不存在，只在日志里留一条 `Unable to start receiver`；
> 用户每跨一次版本就多留一颗。修法：`MainActivity.cancelLegacyReminderAlarm()` 用
> **旧请求码 4202 + 组件名字符串**造等价 PendingIntent 主动撤销（类已删不影响构造，
> 组件名在发送时才 resolve）。机理与**判据自身的坑**见 `docs/工程踩坑总表.md` §7.4 ——
> `grep -c` 整份 `dumpsys alarm` 会因为历史里那条 `reason=alarm_cancelled` 而数出误导性结果。

> ⚠️ **清理后重跑验收，撞出第二个真问题（已修）**：第 1 轮「重启后补排」**FAIL 了** ——
> `BootReceiver` 收到了广播，但 `restorePending` 的三个分支一个都没进（静默返回），
> 说明它读到的 `rushTriggerAt == 0`。而重启后 `run-as cat` 显示**文件里仍是注入值**，
> 即「App 从未读到过」，不是「读到后被覆盖」。
> 真因：`LOCKED_BOOT_COMPLETED` 在 **direct boot** 阶段投递，那时 `shared_prefs`
> （credential-encrypted 存储）**还没解锁、读出来是空的**；解锁后的 `BOOT_COMPLETED` 却能正常读到
> → **同一条路径的成功与否取决于解锁和广播的先后，是竞态**。所以清单里**去掉
> `LOCKED_BOOT_COMPLETED`**，只留解锁后的 `BOOT_COMPLETED`（抢课本来就要已登录的会话，
> 那个会话也在同一个存储里，direct boot 阶段排闹钟毫无意义）。
> 完整机理 + 「怎么判别是读不到而不是写丢了」见 `docs/工程踩坑总表.md` §7.5。

**作废**（备份在 `tools/out/p2_dropped/`，完整补丁 `tools/out/p2_full_20260922.patch`）：

`service/DailyCourseAlarmReceiver.kt`、`service/CourseNotifier.kt`、`service/DailyReminderScheduler.kt`、
`data/OfflineStore.kt`、`data/model/CourseSnapshot.kt`、`data/model/DailyPlan.kt`，
设置项与「我的」页里的提醒 UI（`Preferences` / `SettingsStore` / `SettingsRepository` /
`ProfileScreen` / `ProfileViewModel` 的提醒部分 / `TimetableViewModel` 的快照写入），
以及 `verify_daily_courses.py` / `verify_reminder_live.py` / `verify_course_snapshot.py`。

> 注意：原 `OfflineStore` 混了三个职责（课表快照 / 抢课时刻 / 上次提醒结果），
> 砍掉提醒后只剩「抢课时刻」，所以**没有沿用它的名字** —— 语义对不上的文件留着比删掉更贵。
> 清理后：编译 **0 错 0 警告**，自检回到 **19 组**（提醒的那两组随功能一起撤掉）。

### 0.2 以后排功能的判据（换掉旧的排法）

旧文档（`docs/教务系统可扩展功能分析.md`）是按「**接口好不好挖**」排优先级的，
结果排出来的 T1 里就有两个情境很薄的功能。本轮改用三问：

1. **一个学期里学生真的会用几次？**（低于 4 次的一律压后）
2. **用的时候是不是"非它不可"？**（有没有等效替代）
3. **出错会不会造成不可挽回的后果？**（写操作 / 支付 / 留痕）

排名最前的必须是「**每学期都用、且现在只能开电脑上教务网站才能办**」的那类。

### 0.3 一个重要变化：教务系统**有能力**成为第二数据源

§1 里新挖到的几条把两件事从「做不了」变成「应该是能做」：
成绩单 PDF、主干课程绩点。前者是**报奖 / 保研 / 简历 / 出国都要用**的东西，
现在只能开电脑、登录、点三次、下载 —— 这是本轮最有价值的一个候选。

### 1.3 🆕 成绩单 PDF（带印章）下载链路 —— 本轮最有价值的发现

`score__PersonalScore_js.js` 里完整的三步链路，页面按钮叫「**下载印章成绩**」：

| 步骤 | 接口 | 方法 | 参数 | 说明 |
|---|---|---|---|---|
| ① 列表 | `/SystemManage/PersonalScoreLookFor/GetCjPdfList/{uuid}` | POST | `start` `limit` | 已生成的成绩单文件记录 |
| ② 生成 | `/SystemManage/PersonalScoreLookFor/CreateMyCjPdf/{uuid}` | POST | — | ⚠️ **写操作**：服务端生成 PDF，返回 `Result` + `Data.DocumentNo` |
| ③ 下载 | `/SystemManage/PersonalScoreLookFor/DownLoadMyCjPdf/{uuid}` | POST | `documentNo` | 返回 PDF 文件流（页面用 form target=_blank 提交） |

`GetCjPdfList` 字段（**有印章 / 无印章是两份文件**）：

```
ID, DocumentNo, DocumentState, Xh, Xm, CjCount, XqCount,
NoSignFile（无章版）, SignFile（带章版）, DownLoadCount, CreateTime,
CreateUserId, CreateUserName, CreateUserType, InIp（生成者 IP）
```

**三个必须处理的点：**

1. ⚠️ **前端有硬限制**：`checkIsMangerServer()` 要求 `window.location.host` 是
   `jwgl.jxau.edu.cn` 或 `new.dev.jxau.cn`，否则按钮直接弹「请到教务管理信息系统校园网入口1执行此操作」。
   这是**前端 JS 判断，原生 App 不走这段逻辑** → 但**服务端是否也拦，完全未知**（§6.2 待实测）。
   双通道下的直接后果：**直连通道 host 就是 `jwgl.jxau.edu.cn`（满足）**，WebVPN 回落通道
   host 是 `webvpnnew.jxau.edu.cn`（不满足）→ 即使能通，也要在 UI 上标明「此功能需直连校园网」。
2. ⚠️ **会留痕**：`InIp` 记录生成者 IP、`DownLoadCount` 记录下载次数。属于"对自己"的写操作，
   风险低但不是零 —— 需要在首次使用前明确告知用户。
3. ⚠️ **PDF 含完整学号姓名**：下载后落到手机存储要有明确路径提示，不做自动分享。

## 3. 逐项设计

### 3.A 成绩单 PDF（带印章）下载 ★本轮最优先

**用户路径**：我的 → 我的信息 → 成绩单文件 → （无文件时）「生成成绩单」→ 轮询/刷新 → 「下载」

- 列表页展示 `DocumentNo` / 创建时间 / `DownLoadCount` / **有章版 / 无章版**
- 生成的 PDF 落到 App 私有目录（`filesDir`）再由系统分享，**不写公共存储**，不自动分享
- 双通道：**只有直连通道可用**。WebVPN 回落时按钮禁用并说明原因（"此功能需校园网直连"），
  而不是让用户点了失败（§6.2 实测后再定这个提示是否必要）

**必须处理的坑**（都是这项目踩过的老坑，直接套用）：
- 判据**不能看 `Result`**（`Result` 不可信已 5 例）→ 看正文能否解析成预期结构
- 失败要区分 `null`（失败）与 `emptyList`（成功但为空），空列表 = 「还没生成过任何成绩单」
- 生成是**幂等还是追加**未知 → 先只做"点一次生成一次"，不自动重试（避免连点生成多份留痕）

**验收**：真机直连通道跑通「生成 → 列表出现新行 → 下载得到可打开的 PDF」；
WebVPN 通道下给明确提示而不是静默失败；`logcat` 里不出现 PDF 内容与完整学号。

### 3.B 学分进度 + 主干课程绩点

两块数据拼起来：

1. **应修学分**：`GetPersonalJxjh` 的 `Zxf`（总学分），按 `Kclb`（课程类别）分组，
   另有 `JxjhXiaoJi(zydm + '.' + nj)` → `GET ../JxjhXiaoJi/{uuid}?ZyNjdm=专业代码.年级`（IFRAME 页面，返回 HTML）
2. **已修学分**：从成绩接口按「及格且已出成绩」累计 `Xf`

展示：`类别（必修/选修/通识/实践）→ 已修 X / 应修 Y + 进度条`，外加主干课程绩点表。

- ⚠️ **学分口径要谨慎**：`JxjhXiaoJi` 返回的是 HTML 而不是 JSON，**先确认它有没有数据接口版**；
  没有的话要么解析 HTML（脆弱），要么只做 `GetPersonalJxjh` 的类别汇总（稳）
- ⚠️ **不一致要如实显示**：`Σ已修` 和 `Σ应修` 对不上时**不要抹平**，标出"有 N 门课程未在教学计划中"
- ⚠️ GPA 仍按 §1.2 的口径：只展示服务端 `Point`，`-1` → 「无」

### 3.C 成绩趋势 / 挂科与重修预警（纯本地）

不动教务一行代码，只重算已有成绩：

- 按学期算**加权平均分**与**不及格门数**，画趋势
- 挂科识别用 `Jgbj` 三态（0/1/2）+ `Zpcj` **但 `Zpcj` 可能是文字**，解析失败要显示原文而不是当 0 分
- `Bkcj`（补考成绩）/ `Cxcj`（重修成绩）非空 → 标出"已补考/已重修"，未通过则提示
- ⚠️ 不做「预测能否毕业」这类结论性判断（口径不透明，误导成本高）

### 3.D 找空教室（按上课地点查询）

两种交互，建议都做在一页里：

1. **按教室看整周**：从教室树选教室 → 展示该教室本周占用（复用课表渲染）
2. **按时段找空教室**：选「周几 + 第几节」→ 反查哪些教室空

第 2 种需要**批量**拉教室课表，成本是主要风险：

- 教室树节点数未知（`GetClassroomTree` 裸数组，需实测节点规模；若树只到"楼"层级，
  必须先看每个楼的子节点是否就是教室）
- **不要**一次拉全部教室 → 设计为「按楼按需拉 + 本地缓存（同一学期内课表基本不变）」
- ⚠️ 空教室判断只依据**课表占用**，不含临时借用/考试占用 → UI 上必须写清「仅为课表口径」

### 3.E 培养方案（教学计划）页

`GetPersonalJxjh` 一个接口就能撑起一页：按 `Kclb` 分组的课程清单
（`KcMc` 课程名 / `Zxf` 学分 / `Zxs` `Llxs` `Syxs` 学时 / `Xq` 开课学期 / `Khfs` 考试方式 / `Xklb` 选课类别），
高亮"当前学期应该修但还没选"的课（与已选课表做差集）。

### 3.F 考试倒计时 / 首屏 DDL

- 已有考试数据 → 算「距离最近一场考试还有 N 天」，放在课表页顶部或"我的"页
- ⚠️ 复用 T1 的既有认知：**考试安排在学期初只对有补考的学生有效**
  （`docs/工程踩坑总表.md` 里记着），倒计时卡片在"无考试数据"时要退化成不显示，而不是显示"暂无考试"
- `GetAllKaoShipici` 只作批次起止的旁注，**不要**当成学期日期源

### 3.G 学籍异动并入学籍页

`XueJiYiDongList` 0 行是**正常结果**（不是失败）。有数据时在学籍页底部加一段
「异动记录」：`Ydlx` `Ydyy` `Ydrq` + 异动前后学院/专业/班级对照。

### 3.H 按教师 / 按班级查课表（**边界待议**）

技术上是 `GetKebiao.js` 现成的两个分支。但它不是"查我自己的数据"，而是**查别人**：

- 教务系统本身对学生开放这个页面（属学校公开的排课信息，不涉个人隐私数据）
- 但 App 把它做得比教务更顺手，就**等于给"查某人什么时候在哪上课"提供了便利**（蹭课/找人）
- 建议：**默认不做**。若要做，只做「按班级」（同学之间本来就互相知道课表），
  **不做「按教师」**（指向性更强），并且不做"搜索老师"这类便利检索入口

### 3.I 等级考试信息查看（不报名）

只展示 `GetKjXm` 的项目字典（考试名称 / `BeginTime` `EndTime` 报名窗口 / `Bmf` 报名费）
与 `GetKjmdBySearch` 的可报科目。**报名提交与支付宝支付一律不碰**（§5）。
