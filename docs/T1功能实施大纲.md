## 2. 信息架构：选课 / 抢课合并

### 现状
```
底部导航：课表 | 选课 | 抢课 | 成绩 | 我的     ← 5 项，其中两项高度耦合但被拆开
```
两者本来就是一件事的两半：`SelectionScreen` 的课程行上已经有一个「抢」按钮，点了直接进抢课队列；
`RushScreen` 又只能看到队列与引擎参数，看不到课程在哪。用户要在两个 Tab 之间来回跳。

### 调整后
```
底部导航：课表 | 选课 | 成绩 | 我的            ← 4 项
                  │
                  └─ 内层切换：〔课程 / 已选〕 〔抢课任务〕
```
- 内层用 `SecondaryTabRow`（或顶部 Segment），首层保持「课程」。
- 「课程」= 现有 `SelectionScreen`（范围切换：任选 / 必修 / 已选 + 搜索）
- 「抢课任务」= 现有 `RushScreen` 全部内容（引擎启停、节奏参数、任务列表、定时）
- 课程行上「抢」按钮 → 加入队列后**直接切到抢课视图**并给一条 `Snackbar`，不再需要用户自己找 Tab。

### 实现要点
- `AppRoot.kt` 的 `Tab` 枚举删掉 `Rush`，`Selection` 文案保持「选课」。
- `RushScreen` / `RushViewModel` **不删、不改行为**，只从「顶层 Tab」降级为「选课页的内层视图」。
  它订阅的是 `RushStore` 单例，位置变了订阅不变 —— 这一点已经天然满足，改动面很小。
- ⚠️ 内层切换状态要 `rememberSaveable`，且用**名称**而不是序号存
  （沿用 `ProfileScreen` 里 `ProfilePage.of(name)` 的既有约定，避免以后插视图读错页）。

## 3. 各功能设计

### 3.B 考试安排页 + 考试 .ics

**接口**：`POST /PaiKaoManage/KaoShiAnPaiChaXunManage/GetKaoShiInfo_Student/{uuid}`，body `Xq={term}`。
**现状**：接口早就在用，但**只服务于反推周次锚点，没有页面**。这是最便宜的缺口。

页面内容（按学期分组、按日期升序）：
- 每条：课程名 / 考试类别（正考·补考）/ 日期 / 时间 / 考场 / 座位或人数 / 监考老师
- `Kszhou` 为文字「未定」的行**整条跳过**（实测期末 6/16 条如此），并计入「已跳过 N 条」
- `Ksday` 是 `2026-9-11` **不补零**形态 → 用宽容解析器（项目已有）
- 空数据 `Data: []` 是**正常结果**不是失败 → 文案写「这个学期还没有安排考试」，
  **不要**写成「加载失败」。学期初只有补考是常态。

**考试 .ics 导出**（本阶段即可做，不依赖作息表）：
- 解析 `KsSj` 里的时刻，如 `2026-9-11第02周星期五晚上7：00-9：00`
  → ⚠️ **全角冒号** `：` 与「晚上 7:00」这种中文时段词都要兼容；解析不出时段时降级为**全天事件**
- 每条考试一个 `VEVENT`，`DTSTART` 用 **UTC**（`DTSTART:20260911T110000Z`）：
  中国无夏令时，用 UTC 可完全避开 `VTIMEZONE` 组件，兼容性最好
- `SUMMARY` = `【考试】课程名`，`LOCATION` = 考场，`DESCRIPTION` = 类别/监考
- `VALARM` 两条：考前 1 天、考前 1 小时

### 3.C 学籍信息页

**接口**：`POST /XueJiManage/XueJiManage/GetUserInfo/{uuid}`，Referer 用 `ViewXueJiInfo` 页。
实测 50+ 字段：学号 / 姓名 / 性别 / 民族 / 政治面貌 / 学院 / 专业 / 专业方向 / 班级 /
培养层次 / 学制 / 入学时间 / 学籍状态 / 注册状态 / 在籍状态 …

**两条硬约束**：
1. ⛔ **`Result` 不可信**：该接口返回 `"Result": false` 而 `Data` 是完整档案
   （与成绩接口 `totalCount: 0` 同类）。判据只能是「能否解析出数据」，
   写成 `if (Result == true)` 会把整页判成失败。
2. 🔒 **隐私**：`Sfzh` 身份证号 / `HomeAddress` 家庭住址 / `Homezip` 邮编 / `Ksh` 考生号
   → **默认遮蔽**（身份证只示后 4 位、住址只示到市），点「显示完整信息」再展开。
   不进日志、不进任何导出、不进 `.ics`。

### 3.D 导师信息 + 学期规划

**接口**：
- `POST /OneInfoManage/StudentDaoshiInfo/GetMyDaoshiList/{uuid}`（实测 4 人）
- `POST /OneInfoManage/StudentDaoshiInfo/GetMyXqPlanList/{uuid}`（本人规划 + 导师评语建议）

两页都**纯展示**：导师卡片（姓名 / 职称 / 联系方式 / 指导关系）+ 学期规划条目（学期 / 内容 / 评语）。
合并成「我的信息」分组下的一个子页，还是两个独立子页，见 §8 待决策。

### 3.E 课表 .ics 导出 / 日历订阅

**数据**：现有 `CourseSlot`，其中 `weeks: Set<Int>` 已经是**展开后的周次集合**，可以直接用。
**前置**：`TermAnchor`（第一周周一）+ 节次时刻表（§4）。

- 逐周展开成独立 `VEVENT`（**不用 `RRULE`**：周次常不连续，如 1-16 周去掉期中，
  RRULE 表达不了；逐周展开简单且绝对不会错）
- `UID` 必须**稳定且幂等**：`hash(学期 + 教学班号 + 星期 + 起始节次 + 日期)`
  —— UID 变了会导致日历里出现重复事件，这是最常见的 ICS 坑
- 跳过并计数：`weeks` 为空（周次解析失败）/ `weekday == 0` / 节次解析不出的 slot
  → 页面上显式提示「N 门课无法导出（周次或节次缺失）」，**不静默丢**
- 锚点未知时：**不导出**，提示「先做一次周次校准」并给跳转按钮（见 §5 风险 2）
- 输出：`FileProvider` + `ACTION_SEND`（`text/calendar`）分享到日历 / 邮件 / 微信；
  另给 `ACTION_VIEW` 直接交给系统日历 App

### 3.F 今日课程通知

- 每天固定时刻（默认 07:30，可改）查当天课程 → 有课则发一条汇总通知
  （课程名 / 节次-时刻 / 地点 / 老师），没课不发（可选「今天没课」）
- 依赖锚点判断「今天第几周」→ **锚点未知时不发**，并在设置项旁显示原因
  （「还不知道今天是第几周，先去校准」），不猜、不兜底成第 1 周
- 学期结束后（`todayWeek > 课表最大周次`）自动静默
- 通知点击 → 打开课表页（`PendingIntent` 到 `MainActivity` + extra 指定 Tab）
- 闹钟：复用 `RushScheduler` 的**降级模式**（无精确闹钟权限 → `setAndAllowWhileIdle`）。
  每日提醒不需要秒级精度，**默认就走非精确**，避免申请精确闹钟权限
- ⚠️ **顺手修一个既有缺陷**：`RushScheduler` 没有 `BOOT_COMPLETED` 接收器 ——
  重启后闹钟丢失，定时抢课会静默失效。本轮一并补上 `RECEIVE_BOOT_COMPLETED` + 重启重排。
  （今天课程提醒也受同一问题影响，共用这个接收器。）

### 3.G 桌面小组件（建议缓做）

技术上绕不开：Compose **不能**直接进 `RemoteViews`，只能写 XML 布局 + `AppWidgetProvider` + 手动刷新。
Glance 的依赖在本机缓存里没有（离线约束），不能引。
→ 建议本轮不做，等 P0–P2 落地后单独评估。

## 4. ⛔ 阻塞项：节次 → 钟点表

**事实**：教务系统**不提供**上课的具体时刻。课表接口只给 `Sjd`（`11`/`21` 这种拼接码）与
`Jieci` / `SjdText`（`上午 3-4节`）这类**块名**。
已 grep 全部已抓取的课表 / 教室课表 / 考试安排 JS，**零个钟点命中**；
主菜单 20 项里也没有「作息时间」入口。项目现有代码里同样没有这张表。

**但 ICS 事件必须有 `DTSTART`** —— 没有钟点就写不出日历，也写不出「还有 30 分钟上课」。

三条获取途径，按可靠性排序：

1. **学校官方作息表**（教务处公告 / 学生手册 / 校历附图）—— 最可靠，**需要你提供一次**
2. **教务系统页面兜底探测**：课表页可能有页脚作息说明；或门户首页有「作息时间」公告
   → 可以做一次定向探测（`tools/probe_pages.py`），但成功率不高，**不能当唯一方案**
3. **用户在 App 内填一次**：内置一张可编辑表，首次使用课表导出 / 提醒时引导确认

**我的建议**：方案 1 拿到真值 + 方案 3 作为兜底（用户能自己改）。
**不采用**「内置一份猜的默认值」—— 猜错的作息会让导出的日历**静默全错**，
而且用户不会意识到要去改它。宁可首次使用时明确问一次。

## 5. 风险与边界

| # | 风险 | 处理 |
|---|---|---|
| 1 | `Result` / `totalCount` 不可信 | 全部新接口一律按「能否解析出预期结构」判定，**不看 `Result`** |
| 2 | 锚点推不出来的同学（学期初无补考 → 考试接口 `Data: []`）→ 推不出开学日期 | 课表 .ics 与今日提醒**显式要求先校准**，宁可不做也不给错日期；文案说「校准一次即可，永久有效」 |
| 3 | 学籍页隐私（身份证 / 住址 / 邮编） | 默认遮蔽 + 不进日志 / 导出；`tools/out/` 保持 gitignore |
| 4 | 考试「未定」行、`Kszhou` 是文字 | 整条跳过 + 计数提示，不猜 |
| 5 | 考试时间文本全角冒号 | 解析器兼容全角 / 半角 / 中文时段词，解析不出降级全天事件 |
| 6 | ICS 折行按 **octet**（75 字节）且不能切断 UTF-8 多字节 | 纯逻辑自检必须有中文名跨折行边界的用例 |
| 7 | ICS 的 `UID` 不稳定 → 重复导入产生重复事件 | UID 由稳定输入派生，自检里做「两次导出 UID 集合完全相同」断言 |
| 8 | 设备重启后定时全丢 | 补 `BOOT_COMPLETED` 接收器（顺带修 `RushScheduler` 既有缺陷） |
| 9 | 通知权限（Android 13+ `POST_NOTIFICATIONS`） | 首次开启提醒时请求；拒绝时功能降级为「仅 App 内查看」并明示 |

## 7. 自检与对账方式（沿用项目既有做法）

**离线纯逻辑自检**（无 JVM 单测条件，走 `kotlin-offline-pure-check` 的路子）：
- `IcsWriter`：转义（`\` `;` `,` 换行）、CRLF、**75 octet 折行不切断中文**、两次导出 UID 稳定
- `PeriodClock`：`上午 3-4节` / `下午 5-7节` / `白天 1-8节` / 脏值 → 时刻区间
- 今日课程筛选：周次展开 + 当天 + 锚点未知 / 学期结束后
- 考试时间解析：`晚上7：00-9：00`（全角）、`未定`、`2026-9-11` 不补零

**真机对账**（MuMu `127.0.0.1:7555`）：
- UI 用 `uiautomator dump` 定位，截图核对
- .ics 用本机 Python 解析回来逐条比（**不看截图就说对，等于没验**）
- 通知必须**真的弹出来**才算过
