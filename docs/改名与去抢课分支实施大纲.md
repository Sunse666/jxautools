## 1. 命名与文件夹调整（作用于现有项目 → Pro）

### 1.1 先备份那个「唯一存在」的产物

```
app/build/outputs/apk/release/app-release.apk   7,715,670 B   09-23 11:10
```

`app/build/`、`*.apk` 都在 `.gitignore` 里 —— **仓库里没有它的第二份副本**。后面清缓存会把它抹掉，所以：

1. 复制到仓库之外（建议 `D:\IO\Android\_dist\`）并改名留时间戳，如 `jxautools-pro-20260923-1110.apk`
2. 核对副本大小 = `7,715,670 B` 再往下走

### 1.2 改「名字」（三处，代码零改动）

| 位置 | 现在 | 改成 | 为什么 |
|---|---|---|---|
| `app/src/main/res/values/strings.xml:3` | `<string name="app_name">江农工具箱</string>` | `江农工具箱Pro` | 桌面图标下显示的名字 |
| `settings.gradle.kts` 末行 | `rootProject.name = "jxautools"` | `rootProject.name = "jxautools Pro"` | **Gradle 认的工程名是这个，不是文件夹名** |
| `docs/发布说明.md` §6 首次发布信息 | 「江农工具箱」 | 同步 | 别留下过期描述 |

> ✅ **已核实：没有任何脚本断言应用名**（`grep app_name tools/*.py` 无命中）→ 改这两处不会让任何静态检查变红。

### 1.3 改文件夹名

```bash
mv /d/IO/Android/jxautools "/d/IO/Android/jxautools Pro"
```

- 同一磁盘 → **原子改名，不产生拷贝**（秒级，与仓库 235MB 无关）
- 改名前必须**关掉 Gradle 守护进程与编辑器**，否则句柄占用会失败（`Device or resource busy`）
- ⚠️ 新路径**含空格** → 之后所有命令、脚本参数、`cwd` 都必须加引号。本工程没有 `gradlew`，用的是本机发行版 Gradle，命令行手输时尤其容易漏

### 1.4 清掉「路径敏感」的缓存

删 `./.gradle/`；`./app/build/` 建议一并删（**前提：1.1 的备份已完成**）。

理由：Gradle 的增量缓存里存着**绝对路径**。改名后不清，会出现「明明改了名字，报错却指向旧路径」这类查无可查的怪现象 —— 成本 90 秒重建，换掉一整类玄学。

### 1.5 复验改名没有伤到项目

- `:app:assembleRelease` 零 `e:` 零 `w:`，产出新 APK，时间戳晚于本次改动
- `apksigner verify --print-certs` 指纹仍是 `00:E9:E4:3F:…:97:7F`（证明 `.secrets/` 是相对路径、没被搬家搞断）
- 既有 9 个静态脚本**全绿**（这是「改名没误伤」的对照面）

> ✅ **已核实的两个好消息**：`keystore.properties` 里 `storeFile=.secrets/jxautools-release.jks` 是**相对路径**，`local.properties` 里 `sdk.dir=D:\IO\sdk` 是**绝对路径但指向 SDK 而非工程** —— 搬家都不会断。

## 2. 项目迁移（新建文件夹 = 去抢课版）

### 2.1 新建文件夹

按 D1 定为 `D:\IO\Android\<新文件夹>`。

### 2.2 迁法：用 `git clone --local` 派生，**不要直接拷工作区**

```bash
git clone --local "D:/IO/Android/jxautools Pro" "D:/IO/Android/<新文件夹>"
```

三个理由：

1. **快** —— `--local` 走硬链接，仓库对象不复制
2. **干净** —— 自动排除所有 gitignore 产物：`app/build/`（162MB）、`tools/out/`（56MB）、`.gradle/`、`tools/*.png`
3. **可追溯** —— 保完整历史，删掉 2,365 行这件事在 `git log` 里看得见，随时能 revert

### 2.3 ⚠️ clone **不会**带过来的两个文件（都是 gitignore 的）

| 文件 | 必须手工拷？ | 不拷的后果 |
|---|---|---|
| `local.properties`（`sdk.dir=D:\IO\sdk`） | **必须** | 连编译都起不来 |
| `.secrets/`（keystore + 凭据） | 看 D3 | 打不出能安装的正式包（会退化成一个未签名包，**当场不报错**） |

```bash

cp -r "/d/IO/Android/jxautools Pro/.secrets" "/d/IO/Android/<新文件夹>/"   # 仅当 D3 = 要出正式包
```

（`--local` 克隆时源目录已改名，路径含空格，引号不能省。）

### 7.4 执行中新踩的坑（已写进 `MEMORY.md`「跨仓库 / 目录运维」）

1. **同盘目录改名撞 `Device or resource busy`** —— 根目录被会话工作目录 / 文件监视器持有句柄。
   解法：`mkdir` 新名 + 子项逐个 `mv` + 旧目录留空壳（**文件系统结果等价**，git / Gradle 不关心目录 inode）。
2. **Gradle 增量缓存存的是绝对路径** → 改名 / 搬家后**必须清 `.gradle/` 与 `app/build/`**，
   否则会出现「改了名字却报旧路径」这种查无可查的怪现象。
3. **改名会炸出硬编码绝对路径**（4 处）：`verify_course_palette.py` 直接红（还算走运）；
   但 `kotlin-check/` 的 `run.sh` / `probe.sh` / `probe.py` 是**静默失效**（探针找不到源码却不报错）。
   全仓脚本一律改成 `__file__` / `BASH_SOURCE` 推导 ROOT；**shell 侧不能用 `pwd`**（Git Bash 给 `/d/...`，
   Windows 的 java 解析不了）→ 用 **`pwd -W`**。
4. **`git clone --local` 不拷被 gitignore 的文件**：`local.properties`（不拷编译起不来）与
   `.secrets/`（不拷则**静默退化成未签名包**）必须手工拷并核对大小；`origin` 指向源仓库 → 必须 remove。
5. ⚠️ **沙箱内的大范围删除会被错误应用**：一条未标 `Sandbox bypassed` 的 `git rm` 之后，
   精简版的 `app/` + `tools/` 工作区被整体清空 → 靠 `git checkout -- app tools` 恢复。
   **此后每步都验文件数。**
6. **复现别人的脚本时少一步预处理就会误判**：我第一遍核对 `verify_ui_controls.py` §2 的配对数时，
   直接把正则 group(2) 判 `startswith("on")` 得 0 条，差点得出「这脚本什么都没查」的结论 ——
   实际脚本先做 `last_seg()` 再判，`MaterialTheme.colorScheme.onX` 也算，真值是 2。
7. **「本文件声明的组件为 0」≠「打包后为 0」**：合并后的清单里仍有
   `androidx.profileinstaller.ProfileInstallReceiver`（受 `DUMP` 权限保护）、
   `androidx.startup.InitializationProvider` —— 都是依赖库注入的。看到别慌，先 `aapt dump xmltree` 查来路。
