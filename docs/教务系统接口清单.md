## 1. 挖接口的方法（可复现）

不靠猜、不靠抓包，靠页面自己的 JS —— 教务系统是 ExtJS 写的，所有接口地址都明文写在页面和 JS 里。

```bash
# 1) 从 MuMu 里的调试版取出实时会话（debug 包才能 run-as）
python tools/probe_pages.py pull-cookie

# 2) 抓页面（GET，需要正确 Referer）
python tools/probe_pages.py get "/PaikeManage/KebiaoInfo/GetStudentkebiao/{uuid}"

# 3) 抓它引用的 JS，挖出 url 定义、请求参数、字段名
python tools/probe_pages.py get "Content/UIjs/PaikeManage/KebiaoInfo/GetKebiao.js"
python tools/probe_pages.py mine tools/out/pages/xxx.js

# 4) 按 JS 里的参数发请求验证
python tools/probe_pages.py post "<路径>" "<form-body>" "<该页面的 Referer>"
```

**为什么先用 Python 而不是直接在 App 里试**：安卓侧每验证一条路径都要重编 APK + 装机（约 1 分钟），
Python 改一行就发一次请求。**结论确认后再写进安卓代码**，避免把猜测固化进工程。

## 2. 三个必须知道的机制（不知道就一定踩坑）

### 2.1 ⚠️ 数据接口必须 POST，且必须带必需参数

数据接口（返回 JSON）**只认 POST**，并且**必需的参数一个都不能少**。违反任一条，都会返回
「您没有权限访问该页面,请与管理员联系！」——一个约 1443 字节的 HTML 错误页，而 **HTTP 状态码是 200**。
这个"200 但其实是拒绝"的坑极容易误判成调通了。

实测对照（`GetKcInfo`，同一个 URL）：

| 方法 | 参数 | 结果 |
|---|---|---|
| POST | `start=0&limit=5` | ✅ 正常 JSON |
| POST | `xklb=已选课程&start=0&limit=5` | ✅ 正常 JSON |
| POST | `dummy=1` | ❌ 1443 错误页（缺 `start`/`limit`） |
| POST | 空 body | ❌ 1443 错误页 |
| GET | `?xklb=已选课程&start=0&limit=5` | ❌ 1443 错误页（方法不对） |

所以「必需参数」指的是 `start` / `limit` 这类分页参数（以及各接口自己要求的业务参数，
如课表的 `xq`）；`xklb` 反而是可选的（不给就是查全部开课）。

> 📌 **勘误**：本轮一度判断"守卫按 Referer 授权"。后来的对照实验推翻了它——
> 同一个接口换任意 Referer（甚至不带 Referer）只要参数齐全都能通。
> 当时之所以看起来像 Referer 的问题，是因为第一次实验同时缺了 `start`/`limit`。
> 代码里仍然会带上正确 Referer（与浏览器行为一致、无害），但**它不是通不通的关键，
> 参数和方法才是**。

### 2.2 大小写不能想当然

系统里**同时存在**两套写法，不是笔误：

| 用途 | 写法 |
|---|---|
| 选课页（页面） | `KcManage/GxkcManage/XKStudentList/` ← 小写 `kc` |
| 选课接口（API） | `KcManage/GxKcManage/GetKcInfo/` ← 大写 `Kc` |

排课模块也有两套：`PaiKaoManage`（考试安排）vs `PaikeManage`（课表）。
**抄路径时逐字符核对，别靠记忆。**

### 2.3 响应封装与编码

```json
{ "Message": "", "Result": true, "Data": [...], "OtherData": null, "totalCount": 0, "success": true }
```

- 数组在 `Data`，总数在 `totalCount`
- 有的接口只有 `Result`+`Data`（如学期列表），有的带全套
- 字段名大小写混用很常见（`totalCount` 与 `TotalCount` 都出现过）
- **页面 HTML 是 GBK 编码且不带 meta charset**，按 UTF-8 硬解中文全乱（`tools/probe_pages.py` 已按「声明 → UTF-8 → GBK」顺序自适应）
- ⚠️ **`Result` 不能当成功判据（实测第二例）**：学籍接口 `GetUserInfo` 返回 `"Result": false`
  但 `Data` 里是完整档案。加上成绩接口的 `totalCount: 0`，
  **「看 Result / totalCount 判成败」在这个系统里是错的**；
  唯一可靠的判据是「正文能否解析出预期的数据结构」。

### 2.4 方法：页面 GET，数据接口 POST

- **页面**（三段式路径、返回 HTML）：GET
- **数据接口**（返回 JSON）：**必须 POST**，ExtJS 的 `Ext.data.HttpProxy` 默认就是 POST

同一个路径用错方法会落到 1443 字节的错误页（HTTP 却是 200）。

## 3. 认证链路

完整细节见 `docs/教务系统分析与安卓App大纲.md`。这里只记与接口调用相关的部分：

```
CAS 登录 → TGT（长期，持久化）
TGT → ST（针对 jwgl 签发的一次性票据）   ← 必须用 TGT 现换，不能用登录响应里那个
ST → GET /User/CheckTicketFromSSo?ticket={ST} → 跟随跳转 → /Main/Index/{uuid}
   得到的 Cookie 才是教务系统会话
```

**兑换成功后 CookieJar 里会有三个 Cookie**：

| 名字 | 说明 |
|---|---|
| `ASP.NET_SessionId` | 真正的会话标识，**必须排在 Cookie 头最前**（脚本 `preferred_name` 逻辑） |
| `{uuid}` | 名字就是本次会话 uuid，值是 `ticket=<ST>` |
| `Password` | 值为 `Password`，无实际意义，**脚本会主动过滤掉它** |

> 📌 每次兑换 uuid 都会变（旧会话被顶掉）。所以 **uuid 必须存在会话里跟着走，不能硬编码**。

## 4. 接口清单

基地址：`https://jwgl.jxau.edu.cn`（WebVPN 通道需前缀重写，见第 6 节）
所有路径都带 `/{uuid}`，`{uuid}` = 会话里的 uuid。

**调用约定（否则一定失败）**
1. 数据接口一律 **POST**，form-urlencoded 请求体
2. **带全 `start` / `limit`**（分页参数是所有数据接口的必需项），再叠加业务参数
3. 带该接口所属页面的 Referer（非必需，但与浏览器一致，保留）
4. 判定成功要看**响应体是不是 JSON**，不能只看 HTTP 200

> `GET + 中文查询串` 还需要 URL 百分号编码，否则本地就抛 `ascii codec` 异常，
> 看起来像接口不通（`tools/probe_pages.py` 已处理）。

### 4.1 基础数据

| 接口 | 方法 | 参数 | 说明 | 状态 |
|---|---|---|---|---|
| `/Common/BaseData/GetKsXq/{uuid}` | POST | 无 | **学期列表**（课表/考试/成绩都用它做下拉） | ✅ |
| `/Common/BaseData/GetAllKaoShipici/{uuid}` | POST | `Xq` | 考试批次 | 📖 |
| `/Common/BaseData/GetKsXqTreeForJxrw/{uuid}` | POST | — | 学期树（按教学任务） | 📖 |
| `/User/CheckGuid/?guid={uuid}` | POST | `guid`（=uuid） | **会话票据校验**，不是选课窗口。详见 4.3.1 | ✅ |

`GetKsXq` 实测返回：
```json
{"Message":null,"Result":true,"Data":[{"Key":"20261","Value":"20261","ItemID":0},{"Key":"20252",…}]}
```
学期编码规律：`YYYY` + `1`/`2`，`20261` = 2026 学年第一学期。降序排列，**第一个就是当前学期**。

> ⚠️ **服务端不提供中文学期名**：`Key` 与 `Value` **都是码本身**（`"20261"` → `"20261"`），
> 没有「2026-2027 第1学期」这种可读名称。教务网页上的中文名也是它自己前端拼的 →
> App 里任何形如「2025-2026 第2学期」的文案都必须是**客户端按编码规则推导**的
> （`Term.labelOf`），不要期待接口里有现成字段。

### 4.2 课表（脚本里没有）

| 接口 | 方法 | 参数 | 说明 | 状态 |
|---|---|---|---|---|
| `/PaikeManage/KebiaoInfo/GetStudentkebiao/{uuid}` | GET | — | **本人课表页面**。页面里的 `var Dqxq` 就是当前学期 | ✅ |
| `/PaikeManage/KebiaoInfo/GetStudentKebiaoByXq/{uuid}` | POST | `xq` | **本人课表数据** | ✅ |
| `/PaikeManage/KebiaoInfo/GetClassroomkebiao/{uuid}` | GET | — | 按上课地点查课表（页面） | 📖 |
| `/PaikeManage/KebiaoInfo/DownloadKbinfoToExcel/{uuid}` | GET | `xq` | 导出课表 Excel | 📖 |

Referer 必须是 `https://jwgl.jxau.edu.cn/PaikeManage/KebiaoInfo/GetStudentkebiao/{uuid}`。

**接口不返回 `totalCount`**（实测顶层只有 `Message`/`Result`/`Data`/`OtherData`/`success`），
所以拿不到分页总数，一次给足 `limit`（一学期上百条封顶，`limit=1000` 够）。

**实测响应（真实数据，字段名逐字核对）**：
```json
{"Message":"","Result":true,"Data":[{
  "ID":381744,
  "KcDm":"B2211050746",        // 课程代码
  "KcMc":"Java语言程序设计",     // 课程名称
  "Jxb":"Java语言程序设计2505班", "Jxbbh":"20261132505",   // 教学班名 / 编号
  "KcXz":"课程",                // 课程性质
  "SkZhou":"17",                // 上课周次，如 "1-5,7-16"
  "Rkls":"5342.卢志群",          // 任课老师（带工号前缀）
  "Sjd":"02",  "SjdText":"星期一 上午 3-4节",   // 时间段（代码/文本）
  "XingQi":"1.星期一",  "Jieci":"上午 3-4节",
  "Skdd":"E-104",               // 上课地点
  "Jslb":"多媒体",               // 教室类别
  "Skrs":50,                    // 上课人数
  "KkDw":"软件学院", "KkDwDm":"1105",
  "Skdx":"软件2505",             // 上课对象（可能多班逗号分隔）
  "XueQi":"20261"

```

#### ⚠️ `Sjd` 不是节次序号——是一个拼接码（重要，曾经搞错过）

第一版文档写的「`Sjd` 是两位数字代码，取节次」是**错的**。实测 29 条数据的
`Sjd ↔ XingQi ↔ Jieci` 全表对照后，规律是：

```
Sjd = (星期 - 1) × 10 + 节次块序号
```

节次块序号：`1`=上午 1-2节、`2`=上午 3-4节、`3`=下午 5-6节、`4`=下午 7-8节、
`6`=下午 5-7节、`7`=晚上 9-11节、`9`=白天 1-8节。

于是 `11`/`21`/`31`/`41` **全都是「上午 1-2节」**（分别在周二/周三/周四/周五），
`02`/`12`/`22`/`42` 全是「上午 3-4节」，`09`/`19`/`29`/`39`/`49`/`59`/`69` 全是「白天 1-8节」。

**后果**：拿 `Sjd` 当序号排序，排出来的行序是错的，而且是那种「看着像对的」错。
排周课表的行必须从 `Jieci` 里解析节次区间（`TimetableGrid.parsePeriodRange`）。

#### `Jieci` 的实际取值（一学期 29 条里出现的全部 7 种）

| `Jieci` | 节次区间 | 出现次数 |
|---|---|---|
| `白天 1-8节` | 1-8（全天） | 7 |
| `上午 1-2节` | 1-2 | 5 |
| `上午 3-4节` | 3-4 | 6 |
| `下午 5-6节` | 5-6 | 4 |
| `下午 5-7节` | 5-7（三节连排） | 1 |
| `下午 7-8节` | 7-8 | 5 |
| `晚上 9-11节` | 9-11 | 1 |

注意 `下午 5-6节` 与 `下午 5-7节` 并存，以及 `白天 1-8节` 会覆盖其它所有行。
UI 侧的处理：行集合由**整学期**的 `Jieci` 归纳（不能按当前周归纳，否则切周时行会跳），
按「全天优先 → 起始节次 → 结束节次」排序。

#### `SkZhou` 的实际取值（一学期出现的 19 种）

```
1-16   1-3,6-7,9-14,16   1-4   1-4,6-7,9-17   1-5,7-16   1-5,7-17
1-7,9-13   1-7,9-17   10-11   14   16   17   19-20   2-7,9-17
3,6-7,9-13   3,6-7,9-17   3-4,6-7,9-12   3-5,7-9   4-13   4-5,7-8
```

全部是「逗号分隔 + 连字符区间」形态，没有出现单双周写法。解析器仍保留
`1-16单` / `1-16(双)` 的支持，因为学校换写法时不会通知你。

> 排课表 UI 时用 `XingQi` 取星期、`Jieci` 取节次行、`SkZhou` 判断该周是否上课。
> `SkZhou` 解析失败时必须**返回空集并在 UI 上显式提示**，不能当成「每周都上」或「都不上」。

### 4.2.1 「现在第几周」怎么算（服务端不提供，必须自己推）

服务端**没有**任何开学日期，也没有「当前周次」接口。实测排查过：
`/Common/BaseData/GetKsXq`（学期列表）只有 `Key`/`Value`；`GetKsXqTreeForJxrw`（学期树）
只有 `id`/`text`；课表页面里的 `var Dqxq` 也只是学期编码 `20261`。

**可用的锚点在考试安排里**：`Kszhou`（第几周）+ `Ksday`（该周内的具体日期）构成一个可反推的点。

实测 2026-09-20 抓到的 3 条考试安排：

| 课程 | `Kszhou` | `Ksday` | 该日星期 | 推得该周周一 | 推得第一周周一 |
|---|---|---|---|---|---|
| 线性代数A | `02` | `2026-9-11` | 五 | 2026-09-07 | 2026-08-31 |
| 高等数学D2 | `02` | `2026-9-13` | 日 | 2026-09-07 | 2026-08-31 |
| 大学物理C | `02` | `2026-9-13` | 日 | 2026-09-07 | 2026-08-31 |

3/3 一致 → 第一周周一 = **2026-08-31**。以 2026-09-20（周日）计算 → 第 3 周。

**2026-09-21 复核：这条锚点的覆盖面比原先以为的小得多。** 用真实会话逐学期打接口实测：

| 学期 | 条数 | `Kslb`（考试类别）分布 | `Kszhou` 分布 |
|---|---|---|---|
| `20261`（当前学期） | 3 | **补考 ×3** | `02` ×3 |
| `20252` | 16 | 课程考试 ×14、补考 ×2 | `03`×2、`17`×1、`18`×7、**`未定`×6** |
| `20251` | 10 | 课程考试 ×10 | `19`×5、**`未定`×5** |

关键推论：**学期初的考试安排数据里只有「补考」**（期末考试要到期末才排）。
于是"当前学期能不能推出开学日期"取决于**这个学生有没有挂科**：

- 有补考（本机账号就是 3 条补考）→ 推得出，界面显示「据 3 条考试安排推算，结论一致」
- **没挂科 → `Data:[]` → 推不出**，界面显示「没有可用的考试安排…」，周次停在第 1 周

所以这不是「学期初偶尔推不出」的边缘情况，而是**学期初的常态**：开学前后那几周里，
只有挂科补考的学生推得出来。已用真机复现（把学期切到 `20242` 就得到空列表，
界面文案与同学反馈的一致），复现图 `tools/i1_no_exam_repro.png`。

空数据的响应**仍然是正常对象、不是裸数组**，所以 `fetchAllRows` 不会把它误判成请求失败：

```json
{"Message":"","Result":true,"Data":[],"OtherData":null,"totalCount":0,"success":true}
```

（85 字节。有数据的学期是同一结构、`Data` 非空，长度按行数增长。）

**已知的鲁棒性限制**（要写清楚，不能假装没有）：
- 如上：学期初（及任何该生无补考、期末未排考的时段）**根本推不出来**。这时的行为是：
  周次退回第 1 周，界面上明说「没有可用的考试安排，推算不出开学日期，周次请手动确认」，**不猜**。
- 单条考试录入有误就会带偏。因此取**多数票**，并且把「N 条中 M 条一致」显示在界面上；
  不一致时标红提示「周次可能偏差一周」。
- **`Kszhou` 可能是文字 `未定`**（20252 有 6/16 条、20251 有 5/10 条）。这类条目没有周次，
  必须整体跳过，不能当 0 周或第 1 周用；只有「周次可解析 + 日期可解析」的条目才参与投票。

**其他候选锚点：2026-09-21 逐个实测排除。** 为了不把开学日期吊在考试安排一棵树上：

| 候选 | 实测结果 |
|---|---|
| 学期列表 `Common/BaseData/GetKsXq` | 只有 `Key`/`Value`（两者都是 `"20261"`），无日期 |
| 课表接口 `GetStudentKebiaoByXq` | 16 个字段，**没有任何日期** |
| 课表页面 `PaikeManage/KebiaoInfo/GetStudentkebiao/` | 2146 字节的壳，只带 `xq = '20261'`，无周次 |
| 首页 `Main/Index` | 20079 字节，无日期、无「第 N 周」字样 |
| 消息中心 / 教材 / 评教 / 学籍信息 | 正文里一个日期都没有 |
| 学期规划 `OneInfoManage/StudentDaoshiInfo/MyXqPlan/` | 只有「期末评价填写时间段」（`2026-05-06`~`2026-09-14`），**不是开学日期**。而且这个模块的「当前学期」变量 `dqDsxq` 是 **`20252`**，与教务的 `20261` **不一致** —— 这类字段不能当学期依据 |
| 教学计划 `Jxjh/JxjhManage/PersonalJxjh/` | 出现一个 `2025-09-01`，疑似培养方案版本日期，不是学期起止 |

**结论：教务系统内没有第二个可信的学期日期来源。** 考试安排是唯一的自动来源，
手工设定是唯一可靠的兜底。别再去这几个地方找了。
- `Ksday` 是 `2026-9-11` 这种**不补零**形态，标准 ISO 解析器吃不下（`LocalDate.parse` 会抛异常，
  Python 的 `date.fromisoformat` 同样会抛）。必须自己兜底拆 `y-M-d`。

### 4.3 选课 / 抢课（脚本里已有，这里补全）

#### ⚠️ `totalCount` 会返回 0（分页陷阱）

实测成绩接口有 **27 行数据，但 `totalCount` 是 `0`**。
如果把 `totalCount` 直接当分页终止条件（`已抓行数 >= totalCount` 恒真），
第一批就退出，结果**静默截断成只有第一页**——行数少到看不出来，是最难发现的错。

处理方式：`totalCount <= 0` 时视为「服务端没给总数」，退回靠「本页返回行数 < limit」判断结束。

#### `Jgbj`（结果标记）是三态，不是布尔

| `Jgbj` | 条数 | 含义 | 实测样本 |
|---|---|---|---|
| `0` | 3 | **不及格**（未通过） | 线性代数A 42、高等数学D2 56、大学物理C 44，学期均为 `20252` |
| `1` | 21 | **及格** | 绝大多数行 |
| `2` | 3 | **补考行** | 学期 `20261`、`Kslb`=`补考`、`Zxf`=0、`Bz`=`未入库` |

把 `Jgbj` 当布尔（`== 1`）会丢掉「不及格」和「补考」两种状态，
把补考显示成及格、把不及格显示成及格都是错的。

#### ⚠️ 正考未及格但被补考救回时，`Jgbj` 会变成 1，而 `Zpcj` 仍是正考分

实测两条：

| 课程 | `Zpcj` | `Bkcj` | `Jgbj` | `Point` | `Zxf` |
|---|---|---|---|---|---|
| 大学语文 | 55 | 69 | **1** | 1.5 | 1.5 |
| 高等数学D1 | 56 | 71 | **1** | 1.5 | 4.5 |

也就是说 **`Jgbj == 1` 不代表 `Zpcj >= 60`**。UI 若按「分数 < 60 就标不及格」判断，
这两门会被错误标红；反过来，`Zpcj` 也不是能直接拿来算平均分的最终成绩。
展示时应把这类课单独标成「补考通过」。

#### `Point`（绩点）大部分行没有，**不能用来算平均学分绩点**

实测 27 条里只有 **4 条** `Point` 是真值，其余 23 条全是 `-1.0`。

这 4 条的值：

| 课程 | `Zpcj` | `Bkcj` | `Point` | 是否补考救回 |
|---|---|---|---|---|
| C语言程序设计 | 64 | 无 | 1.4 | 否 |
| 数据结构 | 67 | 无 | 1.7 | 否 |
| 大学语文 | 55 | 69 | 1.5 | 是 |
| 高等数学D1 | 56 | 71 | 1.5 | 是 |

两条无补考的**精确符合** `Point = (Zpcj - 50) / 10`（64→1.4、67→1.7）。
但两条补考救回的都固定是 `1.5`，不符合任何基于分数的公式。

> **结论：这只是假说，样本太少，不足以断定学校的绩点算法。**
> 因此在客户端**刻意不计算平均学分绩点**，只在详情里原样展示服务端给了的那几个值。
> 算错绩点比不显示绩点更糟。（待确认：学校对补考及格的绩点是否统一按 1.5 计。）

#### 学分与统计口径

- `Zxf` 取值实测：`0`、`0.25`、`1`、`1.5`、`2`、`2.5`、`3`、`4`、`4.5`。
  补考行的 `Zxf` 恒为 `0`，所以**不会**造成学分重复计算。
- 学生实际已获学分（按 `Jgbj == 1` 累计）：`41.5`，共 21 门。
- 若统计口径写成「非补考行且 `Zxf > 0`」，则是 24 条（含 3 条不及格）。
  **「口径内条数」与「及格门数」是两个不同的数，别混用。**
- 及格课程的学分加权平均分（只吃 `Zpcj` 是数字的 18 门，学分基数 38.5）= `67.3279`。
  另有 3 门 `Zpcj` 为 `良好`（等级制），没有分数，计学分但无法参与加权。

#### 其他

- `Bz`（备注）实测有 `无` / `未入库`。补考行给 `未入库` = 成绩还没录进系统。
- `Sjcj`、`PJCJ` 实测**恒为 0**，目前无用途。

#### 4.7.1 GPA 公式有官方出处了（推翻"完全无法判断"）

`GetKcPointListByXh` 实测返回一行**公式说明行**：

```json
{ "Kcmcs": "课程平均成绩点（≥2.0才可授予学位）", "Point": -1.0, "Xf": 0,
  "Xq": "<b>GPA</b>", "KcGroupID": 0,
  "Kclb": "0=∑(课程学分 * 成绩点)",
  "Remark": "GPA=∑(课程学分 * 成绩点)/∑ 课程学分" }
```

即 **`GPA = Σ(课程学分 × 成绩点) / Σ 课程学分`**，「成绩点」就是成绩接口的 `Point`。

> **但数值口径不变**：成绩接口里 `Point` 只有 4/27 条是真值，其余 `-1.0`；
> 这个绩点接口本身也只返回说明行（`KcGroupID = 0`），还没有课程组行。
> 所以公式可以写进文档并在 UI 上当口径说明，**App 里仍然不自行计算 GPA**。
> 待确认：课程组行何时出现（是不是「课程分组还没做」，见 §7）。

#### 4.7.2 `Result` 不可信（学籍接口实测 —— 第 4、5 例）

`GetUserInfo` 返回 `"Result": false`，但 `Data[0]` 是完整学籍档案（76 字段，姓名、身份证号、家庭住址…）。
**任何 `if (Result)` 的写法都会把这个页面判成失败。** 判据改为「能否解析出数据」。

同一批实测又添两例（学籍模块内共 3 例，全项目第 4、5 例）：

| 接口 | `Result` | `Data` | 说明 |
|---|---|---|---|
| `GetUserInfo` | `false` | 1 行 / 76 字段 | 完整学籍档案 |
| `GetMyBookReadList` | `false` | **2 行** | 读书清单，数据完好 |
| `GetMyZysyList` | `false` | **4 行** | 专业素养/作业总结，数据完好 |

对照：同一时段 `GetMyDaoshiList` / `GetMyXqPlanList` 返回 `"Result": true` 且 `totalCount` 正确
（2 / 2）—— 说明 `Result` 既不是恒 `false` 也不是恒 `true`，**它只是不能当判据**，
连「同一模块内」都不一致。

> ⚠️ 该接口含**身份证号 / 家庭住址 / 邮编**等敏感信息，App 展示需脱敏且不得落日志、不得导出。

#### 4.7.3 教材 / 评教 / 消息：技术路线不同，别按 ExtJS 的经验试

- **教材（`JcManage/JcLqXsManage/JcLqXsManage`）与评教（`JxcpManage/Xscp/XscpManage`）**
  是 **Ext.NET**（页面里是 `<Ext.Net.InitScriptPlaceholder />` + `WebResource.axd` 里
  编译过的 DirectMethod），不是 ExtJS 的 `Ext.data.HttpProxy`。
  参数序列化方式完全不同，实测两条接口都回 1443 —— 属**独立技术路线，成本高**。
- **消息中心 `GetReceivedMessageByLimit` 是服务端 bug**：稳定返回
  **HTTP 500 +「索引和长度必须引用该字符串内的位置。参数名: length」**，
  换 `limit=10/30` 结果相同。判为**现阶段不可用**，不必再试。

#### 4.7.4 学期规划的两张子表**必须带 `Xq`**

`GetMyBookReadList`（读书清单）与 `GetMyZysyList`（专业素养/作业总结）**不带 `Xq` 就直接
返回 1443 字节错误页**；带上 `Xq={学期码}` 立刻正常（20251：2 行 / 4 行）。

> 这是「错误页 ≠ 接口不存在」的又一实例：很容易把「少传一个参数」误判成「这个子表接口不可用」。
> 实测计数与主表字段**对得上**（20251 书目 2 = `XsBookCount` 2、素养 4 = `XsZysyCount` 4；
> 20252 书目 2 = 2、素养 0 = 0）→ 主表的 `XsBookCount`/`XsZysyCount` **可信**，
> 界面可以据此写「共 N 本」再展开明细。

## 9. 本地 mock 演练（抢课引擎）

抢课是写操作，**窗口没开就没法在真环境验证**（2026-09-21 勘误后：读链路可以真机验，
只有选课/退选这类写操作必须 mock）。`tools/mock_jwgl.py` 就是为此写的本地假教务。

### 用法

```bash
python tools/mock_jwgl.py 8765          # 启动，场景读 tools/mock_scenario.json
```

App 端：「我的 → 进入演练」。会话切到 MOCK 通道，地址 **`10.0.2.2:8765`**
（MuMu/AVD 的 NAT 网关 = 开发机本机）。**不要用 `adb reverse`**——实测它会在
adb daemon 每次重连时被清掉，演练跑到一半断连极难排查。

### 服务端强制执行的契约（客户端必须同时满足）

1. 必须带 `ASP.NET_SessionId=mocksession123` Cookie，否则回「登录信息丢失」失效页；
2. 数据接口必须 POST 且带 `start`/`limit`，缺了回「没有权限访问该页面」；
3. `Xklb`/字段大小写按真系统口径（`GxKcManage` vs 页面 `GxkcManage`）。

### 可编排场景（mock_scenario.json）

| mode | 行为 | 验证引擎的哪条路径 |
|------|------|--------------------|
| `ok` | 直接成功 | 一次提交 + 回查确认 |
| `capacity` | 前 N 次回「人数已满」再放位 | 退避重试、等位策略 |
| `ambiguous` | 前 N 次回执不明（HTTP 200 空壳） | 回查兜底、连续存疑放弃 |
| `expire` | 前 N 次回失效页**并置 sessionLost** | TGT→ST→新会话自愈后再重试 |

`expire` 场景的 `sessionLost` 是全局的：失效后连 `/Main/Index` 校验也回失效页，
直到客户端拿 TGT 兑换新会话。这模拟的是真 CAS 的语义——**会话失效是全局的，
不是单接口的**。第一版 mock 只在 XkInfo 单点失效，自愈成了空操作，被服务端账本对账抓出。

### 账本对账

mock 控制台打出全部请求与判定。**不要只看客户端日志**：2026-09-21 实测
「客户端自报自愈成功」而服务端账本里没有对应 ST 兑换记录——旧 mock 的失效是假的。
对账要点：每次「自愈」都应有 `TGT→ST` + `ST 兑换 → uuid` + 用新 uuid 的请求各一条。

### 已知边界

- mock 的 `User/CheckGuid`、`Getxkqq`、`GetGxkcTree`、`GetKcInfo`、`XkInfo`、`DelXkinfo`
  已实现；`DelXkinfo` 未编排场景，退选演练走默认成功。
- mock 会话 uuid 必须长得像真 UUID（App 的 uuidRegex 按标准格式提取/校验），
  所以用的是 `00000000-0000-4000-8000-00000000000N`。
- 演练模式进出已与会话自愈锁（healLock）串行：在途续期完成前不许切会话，
  续期完成时若会话已被切换则结果作废——这两条是实测踩坑后的修复，见 git log。
