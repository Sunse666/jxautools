## 2. 探测方法（可复现）

```bash
python tools/probe_features.py pull-cookie   # 先取会话（复用 probe_pages.py）
python tools/probe_features.py pages         # ① 20 个菜单页面逐个 GET，记大小 / title / 是否失效
python tools/probe_features.py js            # ② 抓页面引用的 UIjs，从 JS 里挖真实 url 与参数
python tools/probe_features.py verify        # ③ 候选接口逐条 POST（带 start/limit）实测
python tools/probe_features.py dump          # ④ 把高价值接口的完整返回打出来看字段含义
```

**为什么必须先抓 JS**：页面壳里的 `url:` 是 ExtJS 的**相对片段**（`../../KebiaoInfo/GetKebiao`），
直接拿去请求一律 404。真实调用形式（含 `guid` 拼接、`method` 与 `params`）只写在业务 JS 里。
第一轮 `apis` 子命令之所以 0/73 全失败，就是因为跳过了这一步 —— 连已知可用的 `GetKsXq` 都失败，
说明是方法错了而不是接口不存在。

## 3. 实测可用的新接口

以下每一条都是「真实会话 + 正确 Referer + POST + `start`/`limit`」拿到 JSON 后才记录的。
路径统一省略末尾的 `/{uuid}`。

### 3.1 学籍信息 ✅（推荐做）

```
POST /XueJiManage/XueJiManage/GetUserInfo/{uuid}
Referer: /XueJiManage/XueJiManage/ViewXueJiInfo/{uuid}
```

实测字段（50+ 个）：`Xh` 学号、`Xm` 姓名、`Cym` 曾用名、`Xb`、`Csny` 出生年月、`Mz` 民族、
`Jg` 籍贯、`Zzmm` 政治面貌、`Rxlb` 入学类别、`Rxsj` 入学时间、`Xz` 学制、`Yxmc` 学院、
`Zymc` 专业、`Zyfx` 专业方向、`Bjmc`/`Bjjc` 班级、`Pycc` 培养层次、`Sfzh` 身份证号、
`Ksh` 考生号、`Xjzt` 学籍状态、`Zczt` 注册状态、`Zjzt` 在籍状态、`HomeAddress` 家庭住址、
`Homezip` 邮编、`ZcTime` 注册时间……

> ⚠️ **两个必须处理的问题**
> 1. **返回 `"Result": false` 但 `Data` 里有完整数据** —— 这是「Result 不可信」的又一例
>    （与成绩接口 `totalCount` 给 0 同类）。判据必须是「能否解析出数据」，不能看 `Result`。
>    写成 `if (Result == true)` 会把整个页面判成失败。
> 2. **含身份证号、家庭住址、邮编等敏感信息**。App 内展示要脱敏（如身份证只显示后 4 位），
>    且不要落进任何导出 / 日志。

### 3.2 学籍异动 ✅

```
POST /XueJiManage/XueJiManage/XueJiYiDongList/{uuid}
```
fields（JS 里抄自 `ViewXueJiInfo.js`）：`Ydwh` 异动文号、`Ydlx` 异动类型、`Ydyy` 异动原因、
`Ydrq` 异动日期、`Nyxmc`/`Nzymc`/`Nbjmc` 异动后信息。
本机账号 0 行（没人转过专业），**字段结构来自 JS 定义，未用真实数据验证**。

### 3.3 学分绩点（GPA）🟡 关键但需谨慎

```
POST /SystemManage/CJManage/GetKcPointListByXh/{uuid}
fields: ID, Xq, Xh, Bjdm, Kclb, Kcmcs, Kcdms, Xf, Cj, Point, Remark, CreateTime, UpdateTime
```

实测返回 **1 行「公式说明行」**：

```json
{ "Kcmcs": "课程平均成绩点（≥2.0才可授予学位）", "Point": -1.0, "Xf": 0,
  "Xq": "<b>GPA</b>", "KcGroupID": 0,
  "Kclb": "0=∑(课程学分 * 成绩点)",
  "Remark": "GPA=∑(课程学分 * 成绩点)/∑ 课程学分" }
```

**这正是之前「不推断学校算法」那个坑的官方答案**：学校自己的接口里明写了
`GPA = Σ(课程学分 × 成绩点) / Σ 课程学分`，而「成绩点」= `Point` 字段。

但**仍然不能据此就给平均学分绩点**：成绩接口里 `Point` 只有 4/27 条是真值，
其余是 `-1.0`；这个绩点接口本身也还没返回课程组行（只有 1 行说明行、`KcGroupID=0`）。
推测是「课程分组（`KcGroupID`）还没做」或「需要别的入参」——**未验证，不臆造**。

> 结论：公式可以写进文档并在 UI 上作为口径说明；**数值仍然只展示服务端给了的**，
> 不自己拿 `(分-50)/10` 之类的猜想公式去补全。

## 4. 探测中发现的新事实（值得写进接口清单）

1. **`Result` 字段不可信，第二例**。学籍接口 `Result: false` + `Data` 完整。
   加上成绩接口的 `totalCount: 0`，「看 Result 判成败」这类写法在这个系统里是错的。
   **正确判据只有一个：响应的正文能不能解析出预期的数据结构。**
2. **GPA 公式有官方出处**（见 §3.3），此前文档里「不推断学校算法」的措辞应改，
   但**数值口径不变**（只展示服务端给的）。
3. **教材 / 评教 / 消息这三个模块技术路线不同**：
   教材与评教是 **Ext.NET**（`WebResource.axd` 里编译过的 DirectMethod，不是 ExtJS 的 HttpProxy），
   挖法、调用方式、参数序列化都跟现有 14 个接口不是一回事 —— 别按 ExtJS 的经验去试。
4. **消息中心接口本身有服务端 bug**：`GetReceivedMessageByLimit` 稳定返回
   **HTTP 500 +「索引和长度必须引用该字符串内的位置。参数名: length」**。
   这不是我们参数不对（换 `limit=10/30` 都一样），是服务端在某个字段上做了越界 `Substring`。
   **可判定为「现阶段不可用」**，不必再花时间。

## 5. 零接口依赖的增强（性价比最高的一档）

这些不动教务系统一行代码，纯粹是「把已有数据换个用法」，但学生感知最强：

| 功能 | 依赖 | 说明 |
|---|---|---|
| **课表导出 .ics 日历** | 现有课表数据 | 导入系统日历，上课前手机自动提醒。比 App 内通知可靠得多 |
| **课表导出图片 / 分享** | 现有课表渲染器 | 直接复用 `TimetableCanvas.WeekTable` |
| **今日 / 明日课程通知** | 现有课表 + 锚点 | 已有 AlarmManager 与前台 Service 基建（抢课在用） |
| **桌面小组件（今日课程）** | 现有课表 + 锚点 | Glance/widget，需新依赖，需评估离线缓存 |
| **成绩趋势 / 学分进度** | 现有成绩 + 教学计划 | 学分进度用 `GetPersonalJxjh`（脚本已有） |
| **首屏「下一个 DDL」** | 考试安排 + 考试批次 | 考试倒计时 |

> 这些的共同点：**不需要新接口、不受选课窗口 / 写操作风险影响、可以马上验证**。
> 如果只做一件事，我建议先做 **.ics 导出**：改动小、价值直观、零副作用。

## 8. 复现方式

```bash
"$PY" tools/probe_features.py pull-cookie   # 取会话
"$PY" tools/probe_features.py pages         # 页面盘点
"$PY" tools/probe_features.py js            # 挖 JS 里的真实接口
"$PY" tools/probe_features.py verify        # 候选接口实测（只读）

```

写操作（`Save`/`Add`/`Del`/`Submit`/`Confirm`…）在 `verify` 里**只登记不请求**，
这条写在 `probe_features.py` 的 `WRITE_HINTS` 里，改代码时不要放宽。
