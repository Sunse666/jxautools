## 1. 签名密钥：不可逆，先读这段

| 项 | 值 |
|---|---|
| 密钥库 | `.secrets/jxautools-release.jks`（PKCS12，别名 `jxautools`，RSA 2048，有效期至 2056-09-15） |
| 凭据文件 | `.secrets/keystore.properties`（`storePassword` 与 `keyPassword` **相同** —— PKCS12 不支持两者不同） |
| 是否进 git | **否**。`.gitignore` 里 `.secrets/` 与 `*.jks` 都已排除 |
| 证书指纹 | SHA256 `00:E9:E4:3F:92:03:3A:A2:D9:FE:2B:99:BD:3D:BB:C4:95:D5:CA:B5:5E:C9:39:38:F5:CC:AB:43:A6:D9:97:7F` |

⚠️ **立刻把 `.secrets/` 备份到仓库之外**（网盘 / 私密存储 / 密码管理器）。
丢了会怎样，说具体：**已经装过这个包的人无法覆盖升级**，只能卸载重装 ——
而卸载会清空应用数据（登录会话、周次锚点、抢课定时全部丢失，还要重新人工输验证码）。

`app/build.gradle.kts` 在凭据文件**不存在时不报错**，release 会退化成"未签名包"。
这是有意的：新克隆一台机器照样能编译，只是打不出能安装的正式包 —— 比构建直接失败更好定位。

## 2. 为什么正式包是必需品，不是"优化"

`debug` 包的 `android:debuggable = true` → 应用私有目录可被 `run-as` 读取，
那里面存着**教务系统 cookie / uuid / 学号**。只要这个包会到别人手机上，就必须换成 release。

这也是 `buildTypes.release` 里把 `isDebuggable = false` **显式写出来**的原因 ——
它本来就有默认值，但"靠默认值"等于靠别人替你记着。

## 3. 构建与安装

```bash
# 离线构建（本仓库没有 gradlew，用本机 Gradle 发行版）
JAVA_HOME="D:/IO/jdk17" \
  "C:/Users/23836/.gradle/wrapper/dists/gradle-8.10.2-bin/e0thjr3we83usdufs66z371ne/gradle-8.10.2/bin/gradle.bat" \
  --offline --no-daemon --console=plain :app:assembleRelease
```

产物：`app/build/outputs/apk/release/app-release.apk`

### 装之前必须先卸载 debug 包

debug 包用 Android 调试密钥签，release 包用本仓库密钥 —— **签名不同，系统直接拒绝覆盖安装**
（`INSTALL_FAILED_UPDATE_INCOMPATIBLE`）。代价是应用数据清空：要重新登录（**可能要人工输验证码**）、
重新填周次锚点、重新排抢课定时。

### 怎么确认装的是哪个包

**不能用自检项数区分**：debug 与 release 是同一份代码，项数一样。
（"520 vs 654"区分的是**新旧代码**，不是 debug/release。）
要看是否可调试：

- 图形界面：系统设置 → 应用详情，看有无"调试"相关标识
- 命令行：`adb shell dumpsys package cn.edu.jxau.tools | grep -i flags` → 含 `DEBUGGABLE` 才是 debug 包

## 4. 阶段划分：为什么现在不开 R8

| 段 | 内容 | 状态 |
|---|---|---|
| **段 1** | 签名 + release 包，`isMinifyEnabled = false` | ✅ 已完成（2026-09-23） |
| **段 2** | 开 R8 + 补 keep 规则 + **release 包真机冒烟** | ⬜ 未开始 |

**必须分两步的理由**：R8 的失败方式是**运行期静默**的 —— 编译通过、能启动、界面正常，
只是某一处 JSON 解析悄悄返回空。和签名捆在同一步做，出了问题分不清是哪一边的锅。

段 2 的风险面比一般项目小，这三条都核过：

1. 全工程**零 `BuildConfig.DEBUG` 引用** → 没有 debug-only 代码分支，
   release 与 debug 的行为差异只来自 R8 与 debuggable 标记；
2. **没有 `@Serializable`**（只走运行时 `JsonElement` API，且 kotlin-serialization 编译器插件
   不在本机缓存里）→ R8 的类名混淆打不到 JSON 解析；
3. 依赖面窄：compose-bom / okhttp / jsoup / kotlinx-json。

段 2 仍必须验的：jsoup 与 okhttp 的反射/资源依赖是否需要 keep 规则；
R8 之后进程内自检是否仍全绿；`.ics` 导出、会话自愈这些路径有没有被裁掉。

## 5. 分发给同学前必须先处理的事

### 5.1 mock 入口（**必须处理**）

「我的」→ 本地演练 是设置页里的**正式入口**，请求目标是 `10.0.2.2:8765` ——
那是**模拟器回环地址**。真机上点「进入演练」会连不上，而它会把真实会话
`backupSessionForMock()` 切走（退出演练才恢复）。同学误点会以为 App 坏了。

二选一：① 只在 debug 包显示这个入口；② 把 mock 地址做成可配置项。

代码位置：`ui/profile/ProfileScreen.kt`（`ProfilePage.Mock` / `MockPage`）。

### 5.2 权限说明（写给同学）

| 权限 | 为什么 |
|---|---|
| `SCHEDULE_EXACT_ALARM` | 定时抢课要精确触发。Android 12+ 需用户手动授予"闹钟与提醒"，**国产 ROM 常默认拒绝**；未授予时降级为非精确计时，界面上已明示 |
| `POST_NOTIFICATIONS` | 抢课结果通知 |
| `FOREGROUND_SERVICE(_DATA_SYNC)` | 抢课期间保持前台服务 |
| `RECEIVE_BOOT_COMPLETED` | 重启后重建闹钟（缺它时定时抢课会**静默失效**） |
| `INTERNET` / `ACCESS_NETWORK_STATE` | 访问教务系统与 WebVPN |

### 5.3 访问通道

教务系统直连优先，失败回落 WebVPN 重写。**任何一条通道都只在本机执行**，没有中转服务器。
登录密码不落盘（`allowBackup="false"`，且隐私 logcat 已验零命中）。


  产物备份在 `tools/out/release_backup/`（该目录 gitignore；`app/build/` 一清就没了，**必须备份**）。

### 7.5 装包规则（两条都容易踩）

1. **同一 id 的 debug 与 release 不能并存** —— 签名不同，装 release 前必须先卸载 debug 包
   （`INSTALL_FAILED_UPDATE_INCOMPATIBLE`，且会清数据）。
2. **与 Pro 版可以并存** —— id 不同（`.lite` vs 无后缀）。但反过来，**精简版用户想换 Pro 版必须卸载重装**。
