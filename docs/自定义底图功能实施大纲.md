## 0. 已拍板的决策

| 决策点 | 结论 | 一句话理由 |
|---|---|---|
| 作用范围 | 仅课表页 | 课程块不透明、文字对比度不受图影响；改动面最小 |
| 可调项 | 选图 + 清除 + 浓度滑块 | 一个维度就能保证任何图上文字可读 |
| 不做 | 模糊、全局底图、多图轮换 | 模糊要 RenderEffect(API 31+)/预模糊两套实现；全局把列表页可读性问题放大数倍 |
| 图片来源 | 系统 Photo Picker（`PickVisualMedia`） | 零存储权限；`androidx.activity:1.9.3` 已带，不加依赖 |
| 存储 | 拷贝进 `filesDir/timetable_bg.jpg`，prefs 存**文件路径** | photo picker 的 URI 授权是临时的，重启即失效——必须拷贝 |
| 生命周期 | 应用级偏好，**退出登录不清底图** | 与主题/尺寸同类；清了会话不该动用户的个性化 |

## 1. 现状分析（改哪些机制、为什么能落地）

### 1.1 设置链路（全部现成，只需扩三个点）
- **模型**：`data/model/Preferences.kt` 的 `AppPreferences`（不可变 data class 整体替换），
  自检走 `TimetableSizeSpec.selfTest()` 风格：期望值由 Python 独立算、含变异探针。
- **存储**：`data/SettingsStore.kt`（`jxau_settings` 文件，独立于会话文件，退出登录不扫掉）。
- **状态**：`data/SettingsRepository.kt` 单例 + StateFlow，所有写入走 `mutate()`
  （值没变即返回收敛滑块刷屏；**落盘写 `_prefs.value` 最新值**——嵌套重入覆盖坑已有防护）。
- **UI**：`ui/profile/ProfileScreen.kt`「我的」页 = 设置中枢，子页模式（存页名字符串）。
  底图属于「外观」维度 → **加进 `AppearancePage`**，不新开子页
  （外观页已有主题模式/色块墙/自定义色相三节，加一节不破坏结构）。
- **消费端**：`ui/timetable/TimetableScreen.kt` **已在 `collectAsState()` 订阅 prefs**
  ——新增字段天然即时生效，不触碰「设置改了但页面没变」那条静默失效红线。

### 1.2 课表渲染（唯一的结构改动点）
- 页面结构：`Column { Header; Box(weight(1f)) { MotionSwap { … } } }`，页面自身无背景层，
  露的是 `AppRoot` 根 `Surface` 的 `background` 色 → 在 `TimetableScreen` 根部包一层 `Box`
  即可在最底铺图，**不碰** MotionSwap 与布局算术。
- **关键现状**：空格底纹是 `TimetableSurface` 算出的**不透明色**（background 与
  surfaceVariant/outline 按量得比例混合，对比度有逐条断言）。底图若不加处理，
  整个网格区域会被不透明底纹盖死——**「开了底图但格子全是色块」就是这个功能的
  头号静默失效**，见 §3.4。

### 1.3 工具链约束
- 离线构建/编译检查走 `tools/`（`out/build_lite*.log`、`kotlin-check`），零警告是底线。
- `tools/verify_preferences.py` 按「§0 常量独立抄录 + 独立重算期望值」对账 Kotlin 自检，
  新增偏好字段必须同步扩这个脚本，否则出现「两边各自自洽、结论却是错的」。
- 真机/MuMu 验证归用户跑，我的职责是写清单（§6.3）。

## 2. 方案设计

### 2.1 数据层
`AppPreferences` 新增两字段：

```kotlin
/** 课表底图文件路径（filesDir 内）。null = 未启用底图 */
val timetableBgPath: String? = null,

/** 蒙层浓度百分比：30..90，存 5% 网格吸附值。语义 = 蒙层不透明度 */
val timetableBgDim: Int = 60,
```

- **存浓度不存最终 alpha**：同 `CustomAccent` 存「色相+饱和度档」的理由——
  蒙层颜色是 `MaterialTheme.colorScheme.background`（随深浅模式变），派生规则可演进，
  存用户的选择永远有效。
- **存路径不存 URI**：photo picker 返回的 content URI 授权随进程结束失效；拷贝后存路径，
  读取不依赖任何授权，也不引入 `takePersistableUriPermission` 的复杂度。
- `SettingsStore` 新键：`timetable_bg`（String?，null 清键）、`timetable_bg_dim`（Int）；
  读入时 dim 走 `snapDim()` 吸附（夹 30..90、对齐 5% 网格，容错旧值/脏值/手改值）。
- `SettingsRepository` 新增 `setTimetableBg(path: String?)`、`setTimetableBgDim(pct: Int)`
  （内部再 snap 一次，不让非法值进模型）、`clearTimetableBg()`（清 prefs + 删文件）。
  `mutate()` 日志分支：**路径变更记一条**（换图/清除是低频动作，值得留痕）；
  **浓度不记**（滑块每帧回调，刷屏——同 customAccent 的先例）。

### 2.2 图片管道（新文件 `data/TimetableBgStore.kt`）
选图后的落盘流程，全程 IO 线程：

```
PickVisualMedia 回调 Uri
  → contentResolver 读临时流
  → 解码边界（inJustDecodeBounds）→ 按 1440px 上限算 inSampleSize → 降采样解码
  → JPEG ~85% 重压缩（统一格式、控制体积）
  → 写 filesDir/timetable_bg.tmp → rename 覆盖 timetable_bg.jpg（原子替换）
  → settings.setTimetableBg(新路径)
  → 删旧文件（若旧路径存在且 ≠ 新路径）
```

- **顺序不能乱**：先写新文件、再改 prefs、最后删旧文件。反过来任意一步崩溃都会丢图。
- **上限 1440px**：覆盖主流机型屏高的足够分辨率；再大只多占内存不添清晰度
  （显示时还要 `ContentScale.Crop` 缩放）。不为此用 RGB_565：
  图上要叠半透明蒙层，565 的色带会在蒙层过渡处放大。
- **容错**：prefs 里有路径但文件读不到（被系统清理工具删了、备份恢复丢文件）→
  按「无底图」渲染 + 记 `[E]` 日志 + 设置页摘要显示「底图文件丢失」，
  **不崩、也不自动清 prefs**（自动清会把「临时读不到」升级成「设置凭空消失」）。

### 2.3 渲染层（`TimetableScreen`）
```
Box(fillMaxSize) {
  bgPath 非空时: Image(bitmap, ContentScale.Crop, 固定不随滚动)   // 记忆化 + IO 解码
  Box(fillMaxSize.background(background.copy(alpha = 蒙层alpha)))     // 夹在图和内容之间
  原有 Column { Header; … }                                      // 内容不动
}
```

- **层级铁律**：图最底 → 蒙层中间 → 内容最上。表头文字/节次轴/课程块的对比度
  全部由「蒙层 + 原有配色」保证，布局代码零改动。
- **alpha 方向**：`alpha = 1 - dim/100`（dim=90 最浓 → 图几乎看不见）。
  ⚠️ 这里极易写反，实施时以「dim 增大 → 图更看不见」为唯一判据，并写成自检断言（§5）。
- **解码**：`remember(path)` 键控 + `produceState`/`LaunchedEffect` 在 `Dispatchers.IO`
  解码，主线程零解码。path 变化才重解码，拖浓度滑块**不**重解码（dim 不进 remember 键）。
- **Loading/Failed/空态**也铺图（图铺在页面 Box 最底层，天然覆盖所有 phase）。
- **滚动**：图固定不随课表滚动（视差属 P2 不做清单）。

### 2.4 空格底纹（`TimetableSurface` 新变体）
- 现有 `stripesFor(dark)` **保持不动**（无底图时走它，断言体系原样有效）。
- 新增 `stripesForImage(dark)`：底纹格改为 `background.copy(alpha = …)` 半透明
  （奇数行 alpha 低、偶数行 alpha 高，保住「两档可辨 + 描边最显眼」的既有设计意图），
  描边维持不透明或轻微降 alpha。
- 课程块颜色**不变**（不透明）——「文字对比度不受图影响」承诺的根基。
- 选用哪个变体由 `bgPath != null` 决定，从 `TimetableScreen` 传下去；
  `TimetableCanvas`/`WeekTable` 只多接一个参数，几何算术零改动。

### 2.5 设置 UI（`ProfileScreen.AppearancePage` 加一节）
- 「课表底图」分组：
  - 入口行摘要：`关闭` / `已设置 · 浓度 60%` / `底图文件丢失`；
  - 「选择图片」按钮（已设置时文案变「更换图片」）→
    `rememberLauncherForActivityResult(PickVisualMedia)`；
  - 浓度滑块：range 30..90、步长 5，复用 `StepSlider` 的
    「连续拖 + 网格吸附 + 两端形容词」形态（淡 ←→ 浓）；
  - 「清除」按钮：`clearTimetableBg()`。
- **不做独立预览小窗**（P1 再议）：浓度变化切到课表页即可看到（prefs 即时生效），
  外观页再造真渲染器预览的成本先不付。若反馈「调起来不方便」，
  按尺寸子页「实时预览调真渲染器」的既有模式补。

## 3. 风险与已知坑（逐条给判据）

1. **URI 临时授权**：不拷贝、直接存 URI → 重启后图消失（能编译、第一次还好用，
   最阴的静默失效）。判据：真机选图 → 杀进程 → 冷启动图还在。
2. **主线程解码大图**：相机原图 4000×3000 直接 decode ≈ 48MB 内存 + 明显卡顿。
   判据：选一张 10MB 原图，选完到课表无掉帧。
3. **蒙层 alpha 写反**：`1 - dim/100` 的方向。判据：自检断言「dim 单调增 →
   合成色与图色的差单调增」（纯函数判据，不靠肉眼）。
4. **底纹盖死底图**：忘了做 `stripesForImage` → 开了底图但格子区全是色块。
   判据：变异探针——把「开图时仍用不透明条纹」固化成必 FAIL 的用例。
5. **remember 键不全 / 读一次不订阅**：浓度拖动没反应 = dim 没进重组读取路径；
   换图没反应 = path 没进 remember 键。判据：静态检查脚本扫 `TimetableScreen`
   是否从订阅的 `prefs` 读这两个字段（不是在 `load()` 里读一次）。
6. **文件替换非原子**：直接覆盖写 → 写一半崩溃得到损坏图。判据：临时文件 + rename。
7. **mutate 嵌套写入**：新 setter 必须走既有 `mutate()`（落盘写最新值），不自写落盘。
8. **深浅切换**：蒙层颜色随 `background` 自动变深/变浅，机制上无需处理；
   「深色下是否好看」属真机点检项，不做离线断言（诚实标注：只能人看）。
9. **旧版本/降级兼容**：新键缺省 = 关闭，无需迁移；降级装旧版多出的键被忽略，无风险。

## 5. 验证方案（按本项目「自检 + 对账 + 静态检查」纪律）

### 5.1 Kotlin 自检（SelfTest，纯函数）
- `snapDim()`：边界（30/90 保留、29→30、91→90）、脏值（负数、5000、手改 47→45）、
  5% 网格穷举（`30..200 step 7` 全部吸附后落在网格上）。
- **蒙层方向**：`compositeOver(imagePixel, background, alpha)` 的纯函数版——
  断言「dim 单调增 → 合成色与背景的差单调增」（等价于图越来越看不见）。
- **变异探针**：把「开图时用不透明条纹（旧行为）」固化成必 FAIL 用例，
  证明 `stripesForImage` 那组断言确实有判别力。

### 5.2 Python 对账（`tools/verify_preferences.py` 扩展 + 可选新脚本）
- §0 常量表加 `DIM_MIN=30, DIM_MAX=90, DIM_STEP=5`，独立重算 snapDim 期望值。
- 静态断言：`SettingsStore` 必须出现两个新键；`TimetableScreen` 对
  `timetableBgPath`/`timetableBgDim` 的读取必须来自订阅的 `prefs` 变量（grep 级）。

### 5.3 编译与真机
- 离线编译零警告零错误（`tools/` 既有链路）。
- **真机/MuMu 清单（归你跑）**：
  1. 选图 → 课表立即出现底图；2. 拖浓度滑块 → 实时变浓变淡；
  3. 清除 → 恢复纯色；4. 杀进程冷启动 → 底图与浓度还在；
  5. 选一张大原图 → 不卡不崩；6. 切深色 → 蒙层自动变深、文字可读；
  7. 删掉 `filesDir/timetable_bg.jpg` 再启动 → 无底图、不崩、设置页显示「文件丢失」。

## 6. 待确认（不阻塞 P0 开工，动手前你点头即可）

1. 浓度范围与默认值：我定的是 **30..90、默认 60**——想更激进可以放宽下限到 20
   （图更透，但表头文字可读性开始靠运气）。
2. 浓度语义：「浓 = 蒙层浓 = 图更淡」。若你直觉上希望「浓度大 = 图更显」，
   现在改定义成本为零，动手后改要动三处。
3. 底图文件名固定单文件覆盖式（`timetable_bg.jpg`），不做图片库——多张切换属 P2。
